# ts-signer v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a pnpm monorepo where `@ts-signer/core` + `@ts-signer/cli` can login via MTCute, configure check-ins with a wizard, and run scheduled send-text / click-by-text signing; `@ts-signer/electron` is a placeholder only.

**Architecture:** Shared engine in `packages/core` (config, client, actions, scheduler, JSON store). Thin CLI in `packages/cli` (args + wizard). Electron package exists empty for later. Dev workdir defaults to `./.dev-signer` via scripts; product default workdir is `~/.ts-signer`.

**Tech Stack:** Node.js >=24, TypeScript, pnpm workspaces, `@mtcute/node`, zod, croner, citty, `@clack/prompts`, vitest.

**Spec:** `docs/superpowers/specs/2026-10-14-ts-signer-design.md`

## Global Constraints

- Node.js **>=24** (`engines` in root and packages)
- Package manager: **pnpm** only
- Packages: `@ts-signer/core`, `@ts-signer/cli`, `@ts-signer/electron` (placeholder)
- Business logic only in `core`; CLI must not reimplement signing
- No proxy, no multi-account, no topics, no AI, no SQLite, no Electron UI in v1
- Never commit `.dev-signer/`, sessions, or credentials
- Dev scripts must pass `--workdir ./.dev-signer`

`packages/core/src/paths.ts`:

```ts
import fs from "node:fs";
import os from "node:os";
import path from "node:path";

export function resolveWorkdir(explicit?: string): string {
  if (explicit && explicit.trim()) {
    return path.resolve(explicit);
  }
  return path.join(os.homedir(), ".ts-signer");
}

export function workdirPaths(workdir: string) {
  return {
    root: workdir,
    config: path.join(workdir, "config.json"),
    state: path.join(workdir, "state.json"),
    sessionDir: path.join(workdir, "session"),
    credentials: path.join(workdir, "credentials.json"),
  };
}

export function ensureWorkdir(workdir: string): void {
  const p = workdirPaths(workdir);
  fs.mkdirSync(p.sessionDir, { recursive: true });
}
```

**Interfaces:**
- Consumes: `workdirPaths`
- Produces:
  - `interface SignRecordStore { load(): SignState; markSigned(at: Date): void }`
  - `class JsonSignRecordStore implements SignRecordStore`
  - `type SignState = { last_signed_date: string | null; last_signed_at: string | null }`
  - `needSign(state: SignState, signAtCron: string, now: Date, force: boolean): boolean`
  - `computeNextRun(signAtCron: string, now: Date, randomSeconds: number, rng?: () => number): Date`

`needSign` rules (from spec):
- if `force` → true
- if `last_signed_date` is null → true
- if `last_signed_date !==` today's date string (`YYYY-MM-DD` in local TZ) → true
- else: from `last_signed_at`, compute next cron fire; if `next <= now` → true else false

- [ ] **Step 1: Write failing tests** for store round-trip in a temp dir and `needSign` / `computeNextRun` cases (force, never signed, already signed today with next cron in future, crossed next cron)

- [ ] **Step 3: Implement store + schedule**

Use `croner` `Cron` for next run. `computeNextRun`: `next = cron.nextRun(now)` then add `Math.floor(rng() * (randomSeconds + 1))` seconds. Default `rng = Math.random`.

Date string: use local date via format `YYYY-MM-DD` from `now` (respect `process.env.TZ` by relying on `Date` local getters).

    - `clickCallback(chatId, messageId, data): Promise<void>`
  - `signOnce(opts: { config: SignerConfig; bridge: TelegramBridge; store: SignRecordStore; force?: boolean; now?: Date; clickTimeoutMs?: number }): Promise<void>`

Behavior:
1. if `!needSign(...) && !force` return early without marking

   - sleep `action_interval` between actions
   - on chat error: log, continue next chat
   - sleep `sign_interval` between chats
3. after round: `store.markSigned(now)` even if some chats failed
